# vpn.devkz.ru API — контракт глазами клиента (предложение)

Что нужно desktop-клиенту (форк AmneziaVPN) от API, чтобы реализовать
загрузку, обновление и мониторинг профилей. Базируется на текущем
`GET /api/sub/<token>`, расширения помечены **[нов.]**.

## Общие требования

- **Версия API в пути**: `https://vpn.devkz.ru/api/v1/...` **[нов.]** —
  чтобы ломающие изменения не клали старые клиенты.
- **Авторизация**: `Authorization: Bearer <token>` как основной способ
  **[нов.]**; токен в path (`/api/sub/<token>`) оставить как fallback для
  совместимости с обычными WG-клиентами. Токен в URL попадает в логи
  прокси/серверов — Bearer этого избегает.
- **Ошибки единым форматом** **[нов.]**:
  ```json
  { "error": "invalid_token", "message": "Token revoked", "retry_after": 60 }
  ```
  Коды: `401 invalid_token`, `410 token_revoked`, `429 rate_limited`
  (+`Retry-After`), `503 maintenance`. Клиент показывает осмысленные
  сообщения вместо «не удалось скачать».
- **Кеширование**: `ETag` + поддержка `If-None-Match` → `304` **[нов.]** —
  клиент сможет дёшево поллить раз в N минут без перекачки всего списка.

## 1. Список профилей — `GET /api/v1/sub` (есть, доработать)

Текущий ответ устраивает, нужны дополнительные поля:

```json
{
  "name": "iphone",
  "mode": "multi",
  "revision": 42,                        // [нов.] монотонный номер версии списка
  "updated_at": "2026-06-12T18:00:00Z",  // [нов.]
  "profiles": [
    {
      "id": "msk-01",                    // [нов.] СТАБИЛЬНЫЙ id профиля
      "name": "iphone · msk",
      "via": "msk",
      "via_label": "MSK · primary",
      "location": "RU MSK",
      "country_code": "RU",              // [нов.] для флагов в UI
      "priority": 10,                    // [нов.] порядок сортировки/предпочтения
      "tags": ["primary", "fast"],       // [нов.] опционально
      "server": "186.246.13.103",
      "port": 51820,
      "...": "остальные поля как сейчас (ключи, awg, dns, mtu...)"
    }
  ]
}
```

**Зачем `id`:** сейчас клиент сопоставляет профили по `name` при
обновлении (update-in-place). Если имя переименуют на сервере — клиент
создаст дубликат. Стабильный `id` решает это; `name` остаётся свободно
редактируемым отображаемым именем.

## 2. Статусы профилей — `GET /api/v1/sub/status` **[нов.]**

Лёгкий эндпоинт для кнопки «Загрузить доступные рабочие профили» и
индикации живости в сайдбаре без подключения:

```json
{
  "checked_at": "2026-06-12T18:05:00Z",
  "profiles": [
    { "id": "msk-01",    "alive": true,  "latency_ms": 38, "load": 0.42 },
    { "id": "altgw-77",  "alive": false, "reason": "handshake_timeout" }
  ]
}
```

- `alive` — сервер проверяет рабочесть профиля со своей стороны
  (handshake-проба или health-check шлюза) не реже раза в N минут.
- `latency_ms`, `load` — опциональны, пригодятся для сортировки
  «лучший сверху» и авто-выбора.
- Клиент при «обновить» качает `/sub` + `/status` и помечает нерабочие
  профили в списке серым/красным.

## 3. Фидбек клиента — `POST /api/v1/sub/feedback` **[нов., опционально]**

Клиент сообщает результат собственной проверки (кнопка Check / неудачное
подключение), сервер использует это для статистики и алертов:

```json
{ "id": "msk-01", "ok": false, "stage": "handshake", "client_ts": "..." }
```

Ответ `204`. Без чувствительных данных — только id профиля и стадия.

## 4. Открытые вопросы

- **`mode: "single" | "multi"`** — что означает `single`? Если «выдавать
  один лучший профиль», клиенту нужно правило выбора (или сервер сам
  возвращает массив из одного элемента — тогда поле можно убрать).
- **Ротация ключей**: меняются ли `client_private_key`/`psk` при
  перевыпуске? Если да — `revision`/`updated_at` на уровне профиля, чтобы
  клиент знал, что конфиг надо перезаписать, даже если endpoint тот же.
- **Лимиты**: сколько запросов в минуту допустимо на токен (для выбора
  интервала фонового автообновления; клиенту хватит 1 раза в 5–15 минут).

## Использование клиентом (текущая реализация форка)

- Импорт: вставка ссылки в «Add connection» → все профили добавляются
  как серверы, метаданные подписки сохраняются в конфиге сервера.
- Обновление: «Update from vpn.devkz.ru» — повторный фетч всех known
  подписок; совпавшие профили обновляются на месте (сохраняя выбор и
  настройки), новые добавляются, исчезнувшие удаляются.
- Формат `?format=base64` клиентом не используется (он для сторонних
  WG-клиентов), но его стоит сохранить.
